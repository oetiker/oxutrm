## Patch 1 — BLINK, STRIKE, HIDDEN attribute bits

### 1.1 Current bit layout (`src/attrs.rs`, lines 17–22)

```rust
const TEXT_MODE_INTENSITY: u8 = 0b0000_0011;
const TEXT_MODE_BOLD: u8      = 0b0000_0001;
const TEXT_MODE_DIM: u8       = 0b0000_0010;
const TEXT_MODE_ITALIC: u8    = 0b0000_0100;
const TEXT_MODE_UNDERLINE: u8 = 0b0000_1000;
const TEXT_MODE_INVERSE: u8   = 0b0001_0000;
```

`Attrs::mode` is a `u8`. Bits `0b0010_0000`, `0b0100_0000`, `0b1000_0000` are **free**.
`TEXT_MODE_INTENSITY` is a two-bit *mask* (bold and dim are mutually exclusive and share
a field), not a bit — do not treat it as a free-bit neighbour.

**File:** `src/attrs.rs`, immediately after `TEXT_MODE_INVERSE` (line 22).

### 1.7 Escape-code emission — **THIS IS THE PART THAT SILENTLY BREAKS**

Every formatted/diff output method funnels through a single function,
`Attrs::write_escape_code_diff` (`src/attrs.rs`, line ~103), which builds a
`crate::term::Attrs` and calls `write_buf` on it. Confirmed call sites:

| Caller | File:line | Reaches `write_escape_code_diff`? |
|---|---|---|
| `Screen::attributes_formatted` | `screen.rs:518` | **yes, direct** |
| `Screen::contents_formatted` | `screen.rs:290` (+ `grid.rs:221,224,336`) | **yes** |
| `Screen::rows_formatted` | `row.rs:160` `write_contents_formatted` → `grid.rs:336` | **yes** |
| `Screen::contents_diff` | `screen.rs:359` (+ `grid.rs:338,380,385,392,397`) | **yes** |
| `Screen::rows_diff` | `row.rs:307` `write_contents_diff` → `grid.rs:437,444` | **yes** |
| `Screen::state_formatted` | wraps `contents_formatted` | **yes, transitively** |
| `Screen::state_diff` | wraps `contents_diff` | **yes, transitively** |

So **all six named methods plus both `state_*` wrappers need the fix, and all of them get
it from two edits** — one in `attrs.rs` and one in `term.rs`. There is no per-method work.

Without these two edits the new bits parse correctly and `Cell::blink()` returns `true`,
but every formatted and diff output silently omits them. Worse: two `Attrs` differing
*only* in a new bit would produce an **empty** diff (see the early return in
`term::Attrs::write_buf`), so a downstream terminal would keep the stale blink/strike/hidden
state forever. That is the silent-corruption failure mode.

## Patch 2 — addressable scrollback

### 2.0 Naming collision — read this first

**`Screen::scrollback()` already exists** (screen.rs:154) and returns the *viewport offset*
(`usize`). Rust does not permit two inherent methods with the same name on the same type
regardless of arity, so the requested signature

```rust
fn scrollback(&self, from: u64, to: u64) -> Vec<Vec<Cell>>   // WILL NOT COMPILE
```

cannot be added as-is.

**Recommendation: name the new method `scrollback_range(from, to)`** and leave the existing
`scrollback()` / `set_scrollback()` viewport pair untouched. Renaming the old one is a
breaking API change for every current embedder (including ansidrama) for no benefit, and
the two concepts genuinely differ — one is a view offset, the other is absolute content
addressing. If the team prefers the exact requested spelling, the old getter must be
renamed to `scrollback_offset()` in the same commit and the version bumped to 0.17.0.

### 2.1 Current state (verified)

`src/grid.rs`:

```rust
pub struct Grid {
    size: Size,
    pos: Pos,
    saved_pos: Pos,
    rows: Vec<crate::row::Row>,
    scroll_top: u16,
    scroll_bottom: u16,
    origin_mode: bool,
    saved_origin_mode: bool,
    scrollback: std::collections::VecDeque<crate::row::Row>,
    scrollback_len: usize,      // CAPACITY, not fill
    scrollback_offset: usize,   // view offset
}
```

`Grid::scroll_up` (lines 561–577):

```rust
    pub fn scroll_up(&mut self, count: u16) {
        for _ in 0..(count.min(self.size.rows - self.scroll_top)) {
            self.rows
                .insert(usize::from(self.scroll_bottom) + 1, self.new_row());
            let removed = self.rows.remove(usize::from(self.scroll_top));
            if self.scrollback_len > 0 && !self.scroll_region_active() {
                self.scrollback.push_back(removed);
                while self.scrollback.len() > self.scrollback_len {
                    self.scrollback.pop_front();
                }
                if self.scrollback_offset > 0 {
                    self.scrollback_offset =
                        self.scrollback.len().min(self.scrollback_offset + 1);
                }
            }
        }
    }
```

Note the guard: rows are saved **only** when `scrollback_len > 0` *and* no DECSTBM scroll
region is active. Rows scrolled off under an active scroll region are discarded today.

### 2.2 The monotonic counter

**Field.** `src/grid.rs`, in `struct Grid`, after `scrollback_offset`:

```rust
    scrollback_total: u64,
```

**Initialisation.** `Grid::new` (line 19), add to the struct literal:

```rust
            scrollback_total: 0,
```

**Increment.** In `scroll_up`, inside the existing `if` — **not** outside it:

```rust
            if self.scrollback_len > 0 && !self.scroll_region_active() {
                self.scrollback.push_back(removed);
                self.scrollback_total += 1;          // NEW
                while self.scrollback.len() > self.scrollback_len {
                    self.scrollback.pop_front();
                }
                ...
            }
```

**Why inside the guard.** The counter defines the absolute line-number space, so it must
count exactly the rows that entered the ring. Counting evictions that were *discarded*
(scroll-region-active, or capacity 0) would make absolute IDs drift out of sync with ring
contents, and `scrollback_range` would return the wrong lines. The invariant this buys:

> `scrollback_total` = number of rows ever appended to the ring.
> The ring currently holds absolute IDs `[scrollback_total - ring.len(), scrollback_total)`.

Document that invariant as a comment on the field — it is the whole contract.

`u64` never realistically wraps (2^64 rows), so no saturating arithmetic is needed; plain
`+= 1` is fine.

**On `set_size`.** `Grid::set_size` (lines 66–99) does **not** touch `self.scrollback` at
all — it only resizes `self.rows` and clamps cursor/scroll-region state. So the counter and
the ring both survive a resize untouched, and **no change to `set_size` is required.**
Confirmed by reading the function; state it explicitly in the commit message because it is
counter-intuitive (rows truncated by a shrink are destroyed, not pushed to scrollback, so
they must *not* increment the counter — and they don't).

**On entering the alternate screen.** `Screen::enter_alternate_grid` (screen.rs:~697) does:

```rust
    fn enter_alternate_grid(&mut self) {
        self.grid_mut().set_scrollback(0);   // runs BEFORE the mode is set,
        self.set_mode(MODE_ALTERNATE_SCREEN); // so this targets the MAIN grid
        self.alternate_grid.allocate_rows();
    }
```

The alternate grid is constructed as `Grid::new(size, 0)` — capacity 0 — so its
`scroll_up` guard `scrollback_len > 0` is never true. Therefore:

- the alt grid's own `scrollback_total` stays permanently `0`;
- the **main** grid's counter and ring are frozen but fully intact for the whole time
  alt-screen is active;
- on exit, counting resumes exactly where it left off, with no gap.

That is the correct behaviour and needs no code. What it *does* require is §2.5.

```rust
    ///
    /// Monotonically increasing; never reset. The ring currently holds the
    /// absolute range `[scrollback_total() - scrollback_fill(), scrollback_total())`.
    pub fn scrollback_total(&self) -> u64 {
        self.scrollback_total
    }

    /// Number of rows currently held in the scrollback ring.
    ///
    /// This is the *fill*; `scrollback_len` is the *capacity*.
    pub fn scrollback_fill(&self) -> usize {
        self.scrollback.len()
    }

    /// Absolute line number of the oldest row still retained.
    pub fn scrollback_oldest(&self) -> u64 {
        self.scrollback_total - self.scrollback.len() as u64
    }

    /// Borrow scrollback rows by absolute line number, clamped to what is
    /// still retained. Half-open range `[from, to)`.
    pub fn scrollback_range(
        &self,
        from: u64,
        to: u64,
    ) -> impl Iterator<Item = &crate::row::Row> {
        let oldest = self.scrollback_oldest();
        let from = from.max(oldest);
        let to = to.min(self.scrollback_total);
        let (start, count) = if from >= to {
            (0, 0)
        } else {
            (
                usize::try_from(from - oldest).unwrap_or(usize::MAX),
                usize::try_from(to - from).unwrap_or(usize::MAX),
            )
        };
        self.scrollback.iter().skip(start).take(count)
    }
```

`self.scrollback.len() as u64` is a widening cast on all supported targets; the crate has
`#![warn(clippy::as_conversions)]`, so write it as
`u64::try_from(self.scrollback.len()).unwrap_or(u64::MAX)` if the lint is enforced as an
error in CI — check before committing.

### 2.5 `Screen`-level public API

**File:** `src/screen.rs`, after the existing `scrollback()` getter (line 157).

Every one of these reads `&self.grid` **directly, never `self.grid()`**. This is the
critical detail: `Screen::grid()` (line 681) returns `alternate_grid` while alt-screen is
active, and that grid has capacity 0 — so routing through it would report zero history and
return no rows the entire time a TUI app is in alt-screen, making history appear to vanish
and then reappear.

```rust
    /// Total number of rows ever scrolled off the top of the primary screen.
    ///
    /// Monotonically increasing for the lifetime of the `Screen`; never reset
    /// by resizes or by switching to and from the alternate screen. Absolute
    /// line numbers used by [`scrollback_range`](Self::scrollback_range) are
    /// indices into this space: the first row ever scrolled off is line `0`.
    #[must_use]
    pub fn scrollback_total(&self) -> u64 {
        self.grid.scrollback_total()
    }

    /// Number of scrollback rows currently retained.
    ///
    /// Grows until it reaches the configured scrollback length, then stays
    /// there as older rows are evicted.
    #[must_use]
    pub fn scrollback_fill(&self) -> usize {
        self.grid.scrollback_fill()
    }

    /// Absolute line number of the oldest scrollback row still retained.
    ///
    /// Rows below this number have been evicted and cannot be recovered.
    #[must_use]
    pub fn scrollback_oldest(&self) -> u64 {
        self.grid.scrollback_oldest()
    }

    /// Returns scrollback rows by absolute line number, as a half-open range
    /// `[from, to)`.
    ///
    /// The range is clamped to what is still retained, so the result may be
    /// shorter than `to - from`, or empty. Compare the returned length against
    /// the requested span, or call
    /// [`scrollback_oldest`](Self::scrollback_oldest) first, to detect
    /// eviction.
    ///
    /// This always reads the primary screen's scrollback, including while the
    /// alternate screen is active.
    #[must_use]
    pub fn scrollback_range(&self, from: u64, to: u64) -> Vec<Vec<crate::Cell>> {
        self.grid
            .scrollback_range(from, to)
            .map(|row| row.cells_slice().to_vec())
            .collect()
    }
```

#### Eviction policy — recommendation

**Clamp and return fewer rows, plus an explicit `scrollback_oldest()` query.** Chosen over
the alternatives:

- *Return `Err`/`None` on any evicted line* — forces the caller into a retry loop for the
  common case (a UI scrolled to the top of a saturated buffer), where partial data is
  exactly what should be drawn.
- *Pad with blank rows* — silently fabricates content, and the caller cannot distinguish a
  real blank line from a fabricated one.
- *Clamp only, no query* — the caller can infer eviction from a short result, but cannot
  distinguish "evicted" from "asked past the live end", and cannot pre-compute a valid
  request.

Clamping matches Rust slice-range conventions, allocates nothing extra, and makes the
common UI case a single call. `scrollback_oldest()` and `scrollback_total()` together give
the caller the exact valid window `[oldest, total)` up front when it needs certainty.

The returned `Vec<Vec<Cell>>` clones cells (`Cell: Clone`, 32 bytes). For a 10 000-row
request that is ~32 bytes × cols × rows of copying — acceptable for oxuterm's stated use,
but if it ever becomes hot, the borrowing `Grid::scrollback_range` iterator from §2.3 is
already the zero-copy path and can be exposed later without breaking this one.

### 2.6 Alt-screen behaviour summary

| While alt-screen is active | Behaviour |
|---|---|
| `scrollback_total()` | frozen at its pre-alt value, not reset |
| `scrollback_fill()` | frozen, ring fully intact |
| `scrollback_oldest()` | frozen |
| `scrollback_range(a, b)` | returns **primary** screen rows normally |
| counter increments | none — alt grid has capacity 0, guard never passes |
| existing `scrollback()` (offset) | unchanged; forced to 0 on entry, reads alt grid |

On leaving alt-screen the counter resumes with no discontinuity. Nothing is lost and no
absolute line number is ever reused.

### Risks to existing behaviour

**1. `term::Attrs::write_buf` early return — highest risk.** (§1.7b) If the three
`is_none()` clauses are not added, an attribute change involving *only* blink, strike or
hidden emits nothing at all. `contents_formatted` still looks right in most tests because
colours or other attributes usually change too. Guarded by `blink_only_diff_is_not_empty`.

**2. SGR 5/6/8/9/25/28/29 stop reaching `Callbacks::unhandled_csi`.** This is a real
behavioural change for any embedder that currently intercepts these params to implement
blink itself. ansidrama should be checked for such a workaround before this lands; if one
exists it will double-apply. Belongs in the changelog as a breaking-ish note.

**3. The `u8` mode byte is now full.** After this patch there are zero free bits. A future
attribute (overline, extended underline styles, underline colour) forces a widening of
`Attrs::mode` to `u16`. `Cell` has a hard `size_of::<Cell>() == 32` compile-time assertion
(`cell.rs:16`) — widening `mode` alone keeps `Attrs` at its current size only if padding
absorbs it, so that future change may trip the assertion. Not a problem today; worth a
comment at the constant block.

**4. `scrollback_total` counting policy is a judgement call.** Counting only rows that
enter the ring (§2.2) is required for absolute-index coherence, but it means the counter is
*not* "rows that scrolled off the screen" — under an active DECSTBM region, or with
capacity 0, rows scroll away uncounted. If oxuterm's UI presents the number as "total lines
of output", that will under-report for full-screen TUI apps. Document the exact meaning at
the call site.

**5. Reading `self.grid()` instead of `self.grid` in the new `Screen` methods.** (§2.5)
An easy and near-invisible mistake: it compiles, passes every non-alt-screen test, and
makes all scrollback appear empty for as long as a TUI app is running. Guarded by
`alt_screen_freezes_counter_and_keeps_primary_history_readable`.

**6. `clippy::as_conversions` is warned crate-wide** (`lib.rs:41`). The `as u64` in
`scrollback_oldest` will trip it. Use `u64::try_from(...)` if CI escalates warnings to
errors.

**7. Not a risk, but verify:** `Grid::set_size` does not touch the scrollback ring, so a
resize neither reflows nor re-numbers history. Existing truncate-on-resize behaviour is
completely unchanged by both patches.
